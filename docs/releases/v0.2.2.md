## Fixes in 0.2.2

- **Subscription test in *Tools*.** The test sent every config of a subscription to the probes at once, so an agent past its limit of checks on demand answered "this probe is already running 4 checks on demand" and most rows came back unavailable. The configs now go one at a time, each on every picked probe at once and within 5 s.
  - The table shows every config right away and fills in as the checks finish; the current row and the queued ones are marked, with a progress bar on top.
  - *Stop* ends the run and keeps the rows already checked.
  - There is no overall 3-minute limit for a subscription any more: 100 configs that all time out take about 8 minutes.

The single-target test in *Tools* is unchanged (25 s timeout).

## Upgrade

```sh
docker compose pull && docker compose up -d
```

Only the hub changes. Agents installed by 0.2.0 or later update themselves from the hub.

## Русский

### Исправления в 0.2.2

- **Тест подписки в *Инструментах*.** Тест отправлял на пробы все конфиги подписки сразу. Агент, у которого кончался лимит проверок по запросу, отвечал «this probe is already running 4 checks on demand», и большая часть строк приходила как «недоступно». Теперь конфиги идут по одному: каждый проверяется на всех выбранных пробах одновременно и не дольше 5 с.
  - Таблица со всеми конфигами появляется сразу и заполняется по мере проверки. Текущая строка и строки в очереди помечены, сверху полоса прогресса.
  - Кнопка *Стоп* останавливает прогон, уже проверенные строки остаются.
  - Общего лимита в 3 минуты для подписки больше нет: 100 конфигов, которые все упираются в таймаут, займут около 8 минут.

Тест одной ссылки в *Инструментах* не изменился (таймаут 25 с).

### Обновление

```sh
docker compose pull && docker compose up -d
```

Меняется только хаб. Агенты версии 0.2.0 и новее обновятся от хаба сами.
