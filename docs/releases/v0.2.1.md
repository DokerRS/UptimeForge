## Fixes in 0.2.1

- **Subscriptions behind a device limit.** A Remnawave panel with the HWID device limit on answered the hub with a single stub host, because the hub sent no device id. The hub now sends `x-hwid` (plus `x-device-os` and `x-device-model: UptimeForge`).
  - The id is the same on every fetch of one subscription, so the check, its refreshes and a test run in *Tools* take one device slot.
  - It is a hash, so the subscription URL cannot be recovered from it.
  - If the user's devices are all taken, the panel still answers with its "device limit" stub: monitor a subscription with a free slot.
- **Balancers.** An Xray JSON config with a balancer holds several servers; only the first was checked. Every server now gets a check of its own, named `<config> · <tag>`. A server listed in several configs is checked once.

Known limit: a server that connects through another outbound (`dialerProxy`, `proxySettings`) is still checked on its own.

## Upgrade

```sh
docker compose pull && docker compose up -d
```

Agents installed by 0.2.0 update themselves from the hub.

## Русский

### Исправления в 0.2.1

- **Подписки с лимитом устройств.** Если в Remnawave включён лимит устройств по HWID, панель отдавала хабу один хост-заглушку: хаб не присылал идентификатор устройства. Теперь хаб шлёт `x-hwid`, а также `x-device-os` и `x-device-model: UptimeForge`.
  - Идентификатор одинаковый при каждом запросе одной подписки, поэтому проверка, её обновления и тест в *Инструментах* занимают одно устройство.
  - Это хэш, адрес подписки по нему не восстановить.
  - Если у пользователя все устройства заняты, панель по-прежнему отдаст заглушку про лимит устройств. Для мониторинга берите подписку со свободным слотом.
- **Балансеры.** В Xray JSON конфиг с балансером содержит несколько серверов, а проверялся только первый. Теперь у каждого сервера своя проверка с именем `<конфиг> · <тег>`. Сервер, который есть в нескольких конфигах, проверяется один раз.

Известное ограничение: сервер, который подключается через другой исходящий (`dialerProxy`, `proxySettings`), по-прежнему проверяется сам по себе.

### Обновление

```sh
docker compose pull && docker compose up -d
```

Агенты, установленные версией 0.2.0, обновятся от хаба сами.
