## What's new in 0.2.0

### Checker agents
- Volunteer probe points join with a one-time **invite code**: one `join.sh` command installs Docker if it is missing and starts the agent.
- The agent finds out its own network: public address, country and operator (ASN). Checkers are labelled by it.
- A separate **Checkers** tab with invites. Probe pickers are split into infrastructure and checkers.
- Checks are assigned to checkers explicitly. Checks that carry secrets go only to trusted ones.
- A checker going offline or losing its internet is not an alert. Its refusals stay out of the verdict, and it sends no host metrics.

### Signed agent auto-update
- Agents run under a small launcher and update themselves from the hub. Release checksums are signed with Ed25519, and the agent trusts only the key built into it.
- Rollout goes in stages: 1 agent, then 10%, then all. Each stage must connect on the new version before the next one starts.
- The rollout stops and alerts when agents do not come back. Servers go before checkers.
- A version that cannot start is rolled back to the previous one. There are no downgrades.
- Rollout status is shown in the UI.

### Charts
- **Live 1-minute charts**: while someone watches, agents send metrics every second.
- New default chart style, **Zabbix**: filled series, the date and weekday on the axis, and shaded day bands. Two more styles, **smooth** and **mirror** (outgoing traffic drawn below zero), are picked in *Appearance*.
- Drag across any chart to zoom: every chart on the page follows. Double-click to go back.
- Long ranges are downsampled by average, or by max in peaks mode, so a week of load average stays readable.

### Alerts
- **The hub checks its own internet.** When its line drops, its own failures are held, agents are not called offline, and one `probe-net` alert opens after 30 s. Results measured without internet are dropped when the line comes back. No pile of stale notifications after the fact.
- A hub behind NAT judges agents' networks by the public address each agent reports.

### Remnawave and UI
- Servers can be matched to Remnawave nodes by hand, by name or by address. A node's users online are shown in front of the system.
- The indicator palette is picked in *Appearance* and colours the checks page too.
- Secret detection catches more: URLs with credentials, padded, JWT and bot tokens.
- Live streams reconnect with backoff.

### Deploy
- `docker-compose.yml` pins the hub with `UF_VERSION`. Upgrading is `pull` + `up`.

## Upgrade

### 1. The hub

In the folder with `docker-compose.yml`, back up the database, then pull and restart:

```sh
docker compose exec -T postgres pg_dump -U uptimeforge uptimeforge | gzip > backup-pre-0.2.0.sql.gz
docker compose pull && docker compose up -d
```

The database schema is upgraded on start. The compose file from 0.1 keeps working as it is. If `.env` pins a release candidate (`UF_VERSION=0.2.0-rc…`), remove that line to follow `latest`, or set it to `0.2.0`.

### 2. Find the agents that need a reinstall

Agents installed before 0.2.0 have no launcher and cannot update themselves. Open *Settings → General → Agent auto-update*: they are listed under **Update by hand or reinstall**.

### 3. Reinstall each of them, once

On the agent's page open the **⋯** menu → **Rotate token**. The hub shows the install commands with the new token. The running agent disconnects at once, so run the command on that server straight away, the same way it was installed:

- **Script** (`curl … | sudo sh`, systemd): run the new command. It rewrites the service and restarts the agent.
- **Docker Compose**: run the new command. It rewrites `/opt/uptimeforge-agent/compose.yml` and recreates the container.
- **`docker run`**: remove the old container first, then run the new command:
  ```sh
  docker rm -f uptimeforge-agent
  ```

Do not just change the image tag of an old container to `0.2.0`: without the `/state` volume the new command adds, updates are lost every time the container is recreated.

### 4. Check

The agent is online on 0.2.0, and **Update by hand or reinstall** is empty. From now on agents update themselves from the hub, and the hub upgrades with the same `pull` + `up -d`.

These never update themselves; update them by hand on every release:
- plain binaries started by hand;
- Windows and macOS installs;
- OpenWrt and Entware.

Images: `intoxxx/uptimeforge-hub:0.2.0` (also `0.2` and `latest`) and the agent image with the same tags. Binaries are attached below, and `checksums.txt.sig` is the signature agents check.

## Русский

### Агенты-проверяльщики
- Точки проверки от волонтёров подключаются по одноразовому **коду приглашения**. Одна команда `join.sh` ставит Docker, если его нет, и запускает агента.
- Агент сам определяет свою сеть: внешний адрес, страну и оператора (ASN). Проверяльщики подписаны по ней.
- Отдельная вкладка **Проверяльщики** с приглашениями. При выборе проб инфраструктура и проверяльщики разделены.
- Проверки назначаются проверяльщикам явно. Проверки с секретами уходят только доверенным.
- Если проверяльщик ушёл офлайн или потерял интернет, это не алерт. Его отказы не попадают в вердикт, метрики хоста он не шлёт.

### Подписанное автообновление агентов
- Агенты работают под небольшим лаунчером и обновляются от хаба сами. Контрольные суммы релиза подписаны Ed25519, агент доверяет только встроенному в него ключу.
- Раскатка идёт этапами: 1 агент, потом 10%, потом все. Каждый этап должен подключиться на новой версии, прежде чем начнётся следующий.
- Если агенты не возвращаются, раскатка останавливается и поднимает алерт. Серверы обновляются раньше проверяльщиков.
- Версия, которая не стартует, откатывается на предыдущую. Даунгрейдов нет.
- Статус раскатки виден в интерфейсе.

### Графики
- **Живые поминутные графики**: пока кто-то смотрит, агенты шлют метрики каждую секунду.
- Новый стиль графиков по умолчанию, **Zabbix**: залитые серии, дата и день недели на оси, полосы суток. Ещё два стиля, **плавный** и **зеркальный** (исходящий трафик ниже нуля), выбираются во *Внешнем виде*.
- Выделите мышью отрезок на любом графике: все графики страницы подстроятся под него. Двойной клик возвращает назад.
- Длинные периоды прореживаются по среднему, а в режиме пиков по максимуму, поэтому load average за неделю читается.

### Алерты
- **Хаб проверяет свой интернет.** Если у него пропала связь, его собственные сбои придерживаются, агенты не объявляются офлайн, а через 30 с открывается один алерт `probe-net`. Результаты, снятые без интернета, после возврата связи отбрасываются. Пачки запоздалых уведомлений больше нет.
- Хаб за NAT судит о сетях агентов по внешнему адресу, который сообщает каждый агент.

### Remnawave и интерфейс
- Серверы можно сопоставить с нодами Remnawave вручную, по имени или по адресу. Число пользователей онлайн на ноде показано перед системой.
- Палитра индикаторов выбирается во *Внешнем виде* и красит и страницу проверок.
- Поиск секретов ловит больше: URL с учётными данными, токены с дополнением, JWT и токены ботов.
- Живые потоки переподключаются с нарастающей паузой.

### Развёртывание
- `docker-compose.yml` закрепляет версию хаба через `UF_VERSION`. Обновление — это `pull` и `up`.

### Обновление

#### 1. Хаб

В папке с `docker-compose.yml` сделайте бэкап базы, затем скачайте новый образ и перезапустите:

```sh
docker compose exec -T postgres pg_dump -U uptimeforge uptimeforge | gzip > backup-pre-0.2.0.sql.gz
docker compose pull && docker compose up -d
```

Схема базы обновляется сама при старте. Compose-файл от 0.1 менять не нужно. Если в `.env` закреплён релиз-кандидат (`UF_VERSION=0.2.0-rc…`), уберите строку, чтобы следовать за `latest`, или впишите `0.2.0`.

#### 2. Найдите агентов, которых надо переустановить

У агентов, установленных до 0.2.0, нет запускателя, и сами они не обновятся. Откройте *Настройки → Общие → Автообновление агентов*: они перечислены в пункте **Обновить вручную или переустановить**.

#### 3. Переустановите каждого, один раз

На странице агента откройте меню **⋯** → **Перевыпустить токен**. Хаб покажет команды установки с новым токеном. Работающий агент сразу отключится, поэтому выполните команду на его сервере без паузы, тем же способом, каким ставили:

- **Скрипт** (`curl … | sudo sh`, systemd): выполните новую команду. Она перепишет сервис и перезапустит агента.
- **Docker Compose**: выполните новую команду. Она перепишет `/opt/uptimeforge-agent/compose.yml` и пересоздаст контейнер.
- **`docker run`**: сначала удалите старый контейнер, затем выполните новую команду:
  ```sh
  docker rm -f uptimeforge-agent
  ```

Не меняйте у старого контейнера только тег образа на `0.2.0`: без тома `/state`, который добавляет новая команда, обновления будут теряться при каждом пересоздании контейнера.

#### 4. Проверьте

Агент онлайн на версии 0.2.0, а пункт **Обновить вручную или переустановить** пуст. Дальше агенты обновляются от хаба сами, а хаб обновляется теми же `pull` и `up -d`.

Эти сами не обновляются никогда, обновляйте их вручную на каждом релизе:
- бинарник, запущенный руками;
- установки на Windows и macOS;
- OpenWrt и Entware.

Образы: `intoxxx/uptimeforge-hub:0.2.0` (а также `0.2` и `latest`) и образ агента с теми же тегами. Бинарники приложены ниже. `checksums.txt.sig` — подпись, которую проверяют агенты.
